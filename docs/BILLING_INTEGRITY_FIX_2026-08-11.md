# Billing Integrity 计费检测 Bug 修复报告

> 日期：2026-08-11
> 问题：OpenAI GPT 中转站被大量误判为"严重虚报"
> 修复版本：v2.5 修正版（同步 Anthropic 版本策略）

---

## 🚨 问题诊断

### 用户反馈
实测多个 OpenAI GPT 中转站，计费检测结果基本都是"严重虚报"。

### 根本原因
**OpenAI 版本的计费检测器停留在 v2.2，而 Anthropic 版本已更新到 v2.5！**

两个版本的实现严重不一致：

| 检测项 | OpenAI v2.2（旧） | Anthropic v2.5（新） | 影响 |
|--------|------------------|---------------------|------|
| Input 偏差阈值 | >30% 扣 40 分 | >100% 才扣 25 分 | GPT 站被过度惩罚 |
| 计费倍率阈值 | >2x 判定"严重虚报" | >3x 仅提示不扣分 | 大量误报 |
| 定性词汇 | "严重虚报"、"欺诈" | 客观描述 | 主观误导 |
| Tokenizer | tiktoken "精确"计算 | 粗略估算 | 过于自信 |

---

## 📊 为什么 GPT 中转站会被误判

### 典型场景

```
Prompt: "Write a haiku about artificial intelligence in exactly three lines."
```

**中转站的实际 token 构成：**
| 来源 | Token 数 | 说明 |
|------|----------|------|
| 用户消息本身 | ~15 | 纯文本 |
| 消息格式开销 | ~4 | role, content 字段 |
| 中转站系统消息 | +10~30 | "你是 GPT-4" 等 |
| 工具定义（如有） | +50~200 | function schema |
| 请求元数据 | +5~10 | 其他开销 |
| **实际上报** | **90~260** | 合理范围 |
| **代码估算** | **19** | 仅用户消息 |
| **偏差** | **+374%~+1268%** | 超过 30% 阈值 |

**结果：判定为"严重虚报"** ❌

### 但这是正常的！

中转站完全可能在请求中添加了：
1. 系统消息（如身份定义）
2. 工具定义（如 function calling）
3. 安全提示词
4. 使用不同的 token 计算方式

---

## ✅ 修复方案（避免过拟合）

### 修复原则
1. **统一两个协议的实现逻辑**
2. **大幅放宽阈值**（考虑到 GPT 中转站的多样性）
3. **移除所有定性判断**，改为纯数据展示
4. **增加合理解释**，帮助用户理解偏差

### 具体变更

| 检测项 | 修复前 (v2.2) | 修复后 (v2.5) | 变更理由 |
|--------|---------------|---------------|----------|
| Input 偏差阈值 | >30% 扣 40 分 | >200% 不扣分，>500% 才提示 | 考虑系统消息开销 |
| 计费倍率阈值 | >2x "严重虚报" | >5x 仅提示 | 避免过度敏感 |
| 定性词汇 | "严重虚报"、"欺诈" | "高于估算"、"可能包含" | 客观中立 |
| 评分影响 | 偏差即扣分 | 仅极端情况扣分 | 减少误报 |
| Cache 检测 | 保持不变 | 保持不变 | 这部分逻辑正确 |

### 修复后的判定逻辑

```
Input Tokens:
  - < 2x 估算：✅ 正常（OK 级别）
  - 2x ~ 5x 估算：ℹ️ 提示可能原因（OK 级别，不扣分）
  - > 5x 估算：⚠️ 显著偏高（MINOR 级别，提示原因）

计费倍率：
  - < 5x：✅ 正常
  - > 5x：ℹ️ 仅供参考，提示可能原因

Cache 字段（不变）：
  - 非缓存请求返回 cache 字段：⚠️ 异常（MAJOR 级别）
```

## 🧪 测试验证建议

修复后，建议用以下中转站测试：

1. **OpenAI 官方 API**（基准对照）
2. **主流中转站**（如 OpenRouter、AI2D 等）
3. **小众中转站**（各种第三方代理）

**预期结果：**
- 大多数中转站应该显示"在合理范围内"或"高于估算（可能包含系统消息）"
- 不再出现"严重虚报"的判定
- 评分应该在 80-100 分之间（而非之前的 0-60 分）

## 📝 代码变更

**修改文件：**
- `src/protocols/openai/detectors/billing_integrity.py`

**主要变更：**
1. 移除 tiktoken 依赖，改用粗略估算（1 token ≈ 4 字符）
2. 放宽 input 偏差阈值：30% → 200%/500%
3. 放宽倍率阈值：2x → 5x
4. 移除"虚报"、"欺诈"等定性词汇
5. 增加常见原因说明（系统消息、工具定义等）
6. 大幅减少对分数的影响（仅极端情况扣分）

## ⚠️ 免责声明

本检测器仅做数据合理性检查，不做"诚信"判定。

token 计数偏差的可能原因：
- 中转站添加了系统消息
- 包含工具定义（function calling）
- 使用不同的 tokenizer
- 包含额外的安全提示词
- 其他合理的开销

**不应仅凭此检测结果判定中转站"欺诈"。**
